# BioLIMS — лабораторна робота № 5

Навчальна система на основі ЛР3: FastAPI, NGINX, RabbitMQ, Consul та Keycloak. Окремий проєкт і окремі томи Docker Compose (`biolims_lab5`), без модифікації ЛР3.

## Що виконано

- CORS у FastAPI для `https://cad.kpi.ua` та локальної тестової сторінки `http://localhost:8080`. NGINX передає заголовки, не додає їх та не стирає.
- Keycloak + публічний OIDC-клієнт; Authorization Code Flow з PKCE S256 та перевіркою `state`. Демо-сторінка не збирає пароль: його вводять безпосередньо в Keycloak.
- Кожен із трьох сервісів перевіряє підпис RS256 за JWKS Keycloak, `iss`, `aud`, строк дії та тип access token. Без токена повертається 401, без необхідного scope — 403. `/health` і preflight відкриті для перевірок.
- Окремі scopes: `orders.read`, `orders.write`, `assays.read`, `assays.run`, `reports.read`. POST `/api/assays/run` також потребує `orders.read`, оскільки Assay Service передає токен до Order Service.
- Асинхронна логіка ЛР3 із RabbitMQ/SAGA залишається в основі демонстрації.

**Межі:** це локальна навчальна конфігурація, а не production: HTTP без TLS, демонстраційні паролі, відкритий localhost, відсутність MFA та окремого управління правами користувачів. Scopes у Keycloak в цьому прикладі дозволені демо-клієнту; звичайний користувач може їх запросити — це демонструє перевірку scope API, але не повноцінну політику least privilege між користувачами. У пункті 3а методички згадується сторонній identity provider: його підключення окремо описано нижче, без реального облікового запису та OAuth client ID воно не виконане. Реальну роботу з сайту кафедри потрібно погодити та перевірити у його середовищі; preflight лише перевіряє заголовки для зазначеного Origin.

## 1. Підготовка Windows

1. Розпакуйте папку `BioLIMS_Lab5` на `D:\BioLIMS_Lab5`. Потрібен Docker Desktop з Linux containers.
2. Зупиніть попередню ЛР3 у Docker Desktop, щоб звільнити порти 8080, 8500, 5672 і 15672. Не видаляйте її томи. Вікна ЛР4 за потреби можна закрити: ЛР5 для запуску їх не потребує.
3. У PowerShell:

```powershell
cd D:\BioLIMS_Lab5
docker compose up -d --build
docker compose ps
```

Keycloak може завантажуватися кілька хвилин. Відкрийте http://localhost:8180/realms/biolims/.well-known/openid-configuration: якщо сторінка ще не доступна — зачекайте. Бази ЛР5 створюються окремо; запуск ЛР5 не переносить записи зі старої ЛР3.

## 2. Перевірка без авторизації та CORS

Відкрийте http://localhost:8080/api/orders/by-barcode/CODE128-1001 у браузері. Очікується 401: `Bearer token required`.

У PowerShell виконайте команду CORS preflight, імітуючи браузер з Origin кафедри:

```powershell
curl.exe -i -X OPTIONS "http://localhost:8080/api/orders/by-barcode/CODE128-1001" -H "Origin: https://cad.kpi.ua" -H "Access-Control-Request-Method: GET" -H "Access-Control-Request-Headers: authorization,content-type"
```

Очікується HTTP 200 і `access-control-allow-origin: https://cad.kpi.ua`; `authorization` має бути серед дозволених заголовків. Інший Origin (`https://untrusted.example`) не отримає дозвільного заголовка та отримає 400 на preflight. Така перевірка не доводить, що справжня сторінка кафедри може з'єднатися з вашим localhost: на це впливають її код і політики браузера.

## 3. Вхід і доступ із повним набором scopes

1. Відкрийте http://localhost:8080/ у браузері.
2. Залиште перелік scopes, натисніть **Увійти**. Відкриється Keycloak.
3. Навчальний логін: `student`; пароль: `Student123!`.
4. Після повернення на сторінку натисніть **Отримати замовлення**. Очікується 200 і замовлення CODE128-1001.
5. Натисніть **Запустити аналіз**. Очікується 200 і `PENDING_VALIDATION`; після асинхронної обробки натисніть **Отримати звіт**. За необхідності зачекайте кілька секунд.

Для цього у полі scopes потрібні `orders.read`, `assays.run`, `reports.read`. Якщо повторно відкрити сторінку входу, Keycloak може використати вже наявну сесію без повторного введення пароля.

## 4. Перевірка ізольованих scopes

На головній сторінці натисніть **Вийти з демо**, замініть перелік scopes на `orders.read` та знову увійдіть.

- **Отримати замовлення** — HTTP 200.
- **Отримати звіт** — HTTP 403, необхідний `reports.read`.
- **Запустити аналіз** — HTTP 403, необхідний `assays.run`.

Кнопка «Вийти з демо» видаляє токен із sessionStorage; вона не завершує SSO-сесію в Keycloak. Для повного виходу використайте вихід у Keycloak або приватне вікно браузера.

## 5. Сторонній identity provider (потребує дій користувача)

Для буквального виконання п. 3а потрібен обліковий запис зовнішнього провайдера та зареєстрований там OAuth-клієнт. У цьому архіві GitHub/Atlassian не підключений і жодна стороння авторизація не демонструється. Один із варіантів — GitHub OAuth App: у налаштуваннях провайдера зареєструйте client, налаштуйте callback `http://localhost:8180/realms/biolims/broker/github/endpoint`, потім у Keycloak Admin Console → Identity providers → GitHub внесіть видані Client ID і secret. Після цього перевірте кнопку входу та зробіть скріншоти; якщо провайдер відхиляє локальний callback, використайте підтримувану ним адресу та відповідну конфігурацію Keycloak. Не публікуйте секрети на GitHub. Реєстрація і фактична перевірка залежать від користувача та провайдера.

Адмін-консоль: http://localhost:8180/ ; навчальний адміністратор `admin`, пароль `admin-demo-123`. Локальний демонстраційний пароль змініть, якщо середовище буде доступне іншим.

## 6. Скріншоти для звіту

1. `docker compose ps` і discovery URL Keycloak.
2. 401 без токена.
3. CORS preflight із дозволеним Origin, заголовками та, за бажанням, відхилений Origin.
4. Сторінка входу Keycloak і результат авторизації.
5. Замовлення HTTP 200 із scope `orders.read`.
6. Звіт HTTP 403 при токені без `reports.read`; потім звіт 200 з повним scope.
7. Запуск аналізу та результат.
8. За наявності — кнопка реального стороннього identity provider та результат входу.

Не вставляйте access token, authorization code або client secret у звіт чи GitHub.

## 7. Тести

Тести `tests/test_lab5_security.py` перевіряють підпис, issuer, audience, час завершення, тип токена, відсутність scope, 401 та CORS; JWKS у них замінений тестовим ключем. Вони не перевіряють реальний Keycloak, Docker та NGINX.

Попередні `smoke_test.py` і `tests/test_saga.py` залишено з ЛР3 для довідки: вони не адаптовані до JWT та не є тестами готовності ЛР5. Для їх запуску потрібна адаптація до нової авторизації.

Зупинити ЛР5 можна командою `docker compose down` без параметра `-v`. Keycloak у цій демонстрації не має постійного тому: після створення нового контейнера realm імпортується з JSON, а ручні зміни в ньому можуть зникнути.
